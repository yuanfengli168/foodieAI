# FoodieAI MVP1 Brainstorm

> Status: Locked (2026-07-17)
> Owner: Jacky

## Vision

**"Blind ordering prevention"** for travelers via local AI.

A user traveling in China (or anywhere with foreign-language menus) opens the app, takes a photo of a menu (or types a dish name), and gets a structured card describing what the dish is, what it tastes like, and what it looks like — all on-device, no internet required, in <3 seconds.

## User Story (Primary)

> Tourist walks into a Sichuan restaurant in Shanghai. Menu is in Chinese only. No photos. They open foodieAI, take a photo of the menu, see a scrollable list of `<chineseName>(englishName)` entries, tap "麻婆豆腐", and immediately see a card with a real photo, a vivid 2-4 sentence intro, and a flavor profile (spicy / sour / salty / sweet / numbing).

## User Story (Secondary)

> User types "Kung Pao Chicken" directly. App matches the English name to the Chinese entry, shows the same card.

## Data Strategy (Hybrid)

### 800-1000 dishes split into two provenance tiers:

**Tier 1: Real sources (~600 dishes)**
- Wikipedia (Chinese + English)
- 百度百科 (Chinese)
- Each entry has a `source: "wikipedia" | "baidu_baike" | "wikipedia+baidu"` field
- Photos from Wikipedia Commons where available (~40% coverage)
- Emoji placeholders where no photo

**Tier 2: AI-generated (~200-400 dishes)**
- Generated by Qwen 3.5 (cloud batch job, one-time)
- Each entry has `source: "ai_generated"` field
- Photo: emoji placeholder only (no fake photos)
- UI displays **"ℹ️ AI-generated description"** tag on these cards

**Coverage priority** (which dishes get Tier 1):
- Top 200 dishes per major cuisine: 川 (Sichuan), 粤 (Cantonese), 鲁 (Shandong), 淮扬 (Huaiyang)
- Top 200 pan-Chinese staples (宫保鸡丁, 麻婆豆腐, 北京烤鸭, etc.)
- Top 200 dim sum + street food (小笼包, 煎饼果子, 沙县小吃, etc.)
- Remaining 200-400 are regional specialties and rare dishes → Tier 2

**For Western dishes (~200)**:
- Top 200 common Western dishes travelers might encounter in mixed menus
- Sourced from Wikipedia English
- Photos from Wikimedia Commons where available

## Tech Stack

| Layer | Choice | Why |
|---|---|---|
| UI | SwiftUI | Native, fast, good for card layouts |
| LLM runtime | MLX-Swift (mlx-swift-examples) | Best Apple Silicon perf, MIT |
| LLM model | Qwen 2.5 3B Instruct (4-bit) | Best ZH/EN balance, Apache 2.0 |
| OCR | Vision framework (Apple) | Free, on-device, CJK support |
| Vector store | Custom flat-file (JSON + cosine sim) | Small dataset, no need for sqlite-vec |
| DB seed generation | Qwen 3.5 (cloud batch) | High quality Chinese content |
| Photo bundling | Compressed JPEGs (80-100KB each) | 800 photos ≈ 80MB |
| RAG embeddings | bge-small-zh-v1.5 (384-dim) | 50MB, Chinese-tuned |

## Search Strategy (MVP1)

- **Exact match only** in EN/ZH
- Pinyin without tones (e.g., "mapo doufu" → 麻婆豆腐)
- No fuzzy matching (MVP2)
- If no match: show "dish not found" error message

## Error Handling

| Error | Behavior |
|---|---|
| Dish not found in DB | Show "Dish not found" card, suggest checking spelling |
| RAG backend error | Show "Something went wrong" with retry button |
| LLM generation failure | Show pre-cached description from DB (fallback) |
| OCR confidence low | Show "Couldn't read menu clearly — try a clearer photo" |
| No CJK characters detected | Skip translation step, describe EN dishes |

## Out of Scope (MVP2+)

- Allergens / dietary restrictions
- Online API fallback (paid tier) — see mvp2-paid.md
- Image generation
- Animation / video
- User-contributed photos
- Fuzzy dish name matching
- Languages beyond EN/ZH
- Offline DB updates
- Voice input
- AR overlay
